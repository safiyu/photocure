## 1. Rules of Engagement & Global Invariants

Every agent or engineer working from this plan must strictly adhere to these fundamental principles:

1. **Sequential Commit Groups**: Work through **C1 to C6 in exact order** directly on `develop`. **Do not start the next commit group until every automated and manual acceptance test of the current group passes.** Each group is one commit, or a tight series of commits sharing the `C<n>:` subject prefix. Do NOT push until the user asks (per project convention).
2. **Never Invent APIs**: When this plan references a function, file, or column that you cannot find, search the repository first (`git grep`, `rg`, or Python AST search), adapt to what already exists, and note the adaptation in the commit body.
3. **Small, Local Diffs**: Do not reformat files, change quote styles, or refactor unrelated code. Keep changes targeted to the requirements of the active commit group.
4. **License & Dependency Tracking**: Every newly introduced dependency must be declared in `pyproject.toml`. Every bundled model, weight file, or third-party asset must be documented in a top-level `NOTICE` file in the very same commit group.
5. **No Hard-Coded Numeric Thresholds**: All numeric thresholds (e.g. EAR cutoffs, blur gates, timeouts, batch sizes) are starting defaults marked `(tune)`. They must be loaded from `photocure/config.py`, never hard-coded. Never publish speed or accuracy figures until the benchmark commands in C3 produce empirical numbers on real photo sets.
6. **XSS Prevention & DOM Node Safety**: **Never use `innerHTML` with text originating from the database, filesystem, or user input.** Always use `textContent` or construct safe DOM nodes via `document.createElement()`.
7. **Absolute Ledger Integrity**: **Never write to, move, or delete an original photo on disk except through the existing transaction ledger (`ActionEngine`)**, which must preserve full undo capability via `RollbackEngine`.
8. **Schema Versioning**: SQLite schema changes land through a single `schema_version` table (added in C1 if absent). Each commit group that alters tables bumps the version by 1, registers an idempotent `migrate_to_vN()` step, and the `migrate()` entrypoint applies missing versions in order on startup. No group adds columns via ad-hoc `ALTER TABLE` outside this mechanism.
9. **Per-Group CI Gate**: C1 introduces a minimal GitHub Actions workflow (`.github/workflows/ci.yml`) running `pytest`, `ruff`, and the Node virtual-grid tests (added as no-op skeleton until C4). Every subsequent commit group extends it; the next group does not start until CI on the HEAD of `develop` is green.
10. **Burst Definition**: A "burst" is a run of photos from the same camera (`exif.camera_model`) whose consecutive `taken_at` deltas are all `<= cfg.burst_gap_seconds` (default 2.0, tune). The burst is bounded by the first delta exceeding the gap or by a camera-model change. Where EXIF `BurstUUID` / `BurstID` is present it takes precedence over the time heuristic. All burst-relative logic (face tracking, blink baseline, best-shot selection) uses this definition.

### Core Architectural Decisions Applied Globally
- **Offline & Privacy-First**: The web dashboard makes **zero external network requests**. Fonts, scripts, styles, and SVG icons are 100% self-hosted and bundled. The backend makes zero outbound requests, with the sole exception of the first-run dependency install (per §2.4 bootstrap). Any outbound integration with third-party photo managers is explicitly out of scope for C1 to C6 and is tracked in §10 Roadmap.
- **Local by Default & Comprehensive Route Protection**: The server binds to `127.0.0.1` by default. **All API endpoints and media routes (thumbnails, face crops, image streams) require authentication**. Loopback alone is not treated as a security boundary; the server validates client socket IP, enforces a Host header allowlist, and requires CSRF Origin validation to prevent malicious web pages from accessing user photos or triggering mutations via DNS rebinding.
- **Per-User Virtual Environment**: The AI stack lives strictly in a user-owned directory (`~/.local/share/photocure/venv`), never in `/opt` or world-writable system paths (`chmod 777` is strictly forbidden).
- **Permissive Model Licensing**: InsightFace and its `buffalo_l` weights are eliminated. Face presence is detected via **OpenCV YuNet** (BSD-3 Clause); eyelid landmarks and blink evaluation are performed via **MediaPipe FaceLandmarker** (Apache 2.0). Face recognition, identity clustering across albums, and person naming are out of scope for C1 to C6 (see §10 Roadmap).
- **Flag, Never Auto-Cull**: Closed-eye and blink detection applies a score penalty and displays a badge. Photocure **never automatically deletes or moves a photo on its own**.
- **Non-Destructive Sidecar Writes**: Photocure's XMP writer modifies only the fields it owns (`xmp:Rating`, `xmp:Label`, flat `photocure-*` tags under `dc:subject`) and preserves every other element and attribute byte-for-byte. This is a correctness invariant for Photocure's own use, independent of whether any other tool reads the sidecars; third-party-tool interoperability testing is deferred to §10 Roadmap.
- **Project License is MIT & Author is Safiyu**: `LICENSE` file at repo root, `pyproject.toml`, AppStream XML, UI headers, and About cards must specify **MIT** and credit author **Safiyu** (`Safiyu Vattaparambil`).

## 2. C1: Safety, Security, Lifecycle & Confirmation System

**Goal**: Fix all high-risk installation, process control, network exposure, and filesystem mutation hazards before introducing new features.

### 2.1 Complete Route Protection, One-Time Code Cookie Exchange, Host Allowlist & Docker Token Generation
* **Loopback Security & Threat Model**:
  - Loopback is not a trust boundary: any web page open in a user's browser can issue requests to `http://127.0.0.1:8080`, and DNS rebinding attacks can bypass same-origin protections.
  - Read endpoints (`/api/images`, `/thumbnail/*`, `/api/faces/*`) expose private personal photos; mutating endpoints (`/api/scan`, `/api/plan/apply`, `/api/settings`) execute filesystem mutations.
  - **Rule**: Require valid authentication on **all `/api/*` endpoints and media routes**. Exempt **only** `/healthz` and the static HTML shell (`/`, `/static/*`).
* **One-Time Code (OTC) Cookie Exchange**:
  - Unconditional cookie delivery on `GET /` allows any local user or script reaching port 8080 to obtain access.
  - **Mechanism**:
    1. When the CLI/launcher starts (`photocure start` / `serve`), it generates a cryptographically secure one-time authorization code (`otc`, 32 urlsafe bytes).
    2. The browser is opened to `http://127.0.0.1:8080/#code=<otc>` (fragment, not query). The static shell reads `location.hash`, POSTs the code to `POST /auth/exchange` as JSON, then calls `history.replaceState(null, '', '/')` to clear it. Rationale: query strings land in access logs, Referer headers, and browser history; fragments do not leave the browser.
    3. The server validates `<otc>`, sets an `HttpOnly`, `SameSite=Strict`, `Path=/` session cookie (`pcur_session=<token>`), invalidates `<otc>`, and responds `204 No Content`.
    4. Access logging config must exclude the request body of `/auth/exchange` and must not log `Authorization` or `X-PCUR-Token` headers.
    5. If `--no-open` is passed, the OTC is printed to the terminal (never written to disk) and the user pastes it into the auth modal.
    6. If a user visits `/` without a valid cookie or code, the static shell renders an authentication modal prompting for the token. The shell MUST contain no user data, no library paths, and no version strings beyond the public `GET /api/about` payload.
    7. API requests accept authentication either via the `pcur_session` cookie or the `X-PCUR-Token` header.
* **Persistent Token Storage in Data Directory**:
  - Ephemeral tokens invalidate on `os.execv` restart, logging the user out.
  - Store the persistent session token in `Path(cfg.cache_dir).parent / "auth_token"` (default: `~/.local/share/photocure/auth_token`, mode `0600`).
  - In Docker, this lands inside the mounted persistent data volume (`/data/auth_token`).
* **Docker Container Token Generation**:
  - Inside containers, `--host 0.0.0.0` is required. If `PCUR_AUTH_TOKEN` is unset when binding `0.0.0.0`, the container automatically generates a secure token on first launch, prints it prominently to stdout (`console.print("[bold yellow]Initial authentication token:[/bold yellow] ...")`), saves it to `/data/auth_token`, and starts cleanly.
* **Host Header Allowlist & Reverse Proxy Support (`PCUR_ALLOWED_HOSTS`)**:
  - Prevent DNS rebinding attacks with strict Host allowlisting.
  - In `photocure/config.py`: Add `allowed_hosts: str = ""` (reads `PCUR_ALLOWED_HOSTS`, comma-separated).
  - Allowlist contains: `{"localhost", "127.0.0.1", "[::1]", f"localhost:{port}", f"127.0.0.1:{port}", f"[::1]:{port}"}`, the configured bind host, plus any hostnames/IPs listed in `PCUR_ALLOWED_HOSTS` (e.g. `photos.lan`, `photocure.local`).
  - Reject requests with unlisted Host header with HTTP `400 Bad Request`.
* **Client IP & CSRF Origin Guard**:
  - Loopback status is determined strictly from socket peer address (`request.client.host`), **never** from the `Host` header. This check is only meaningful when the server binds a non-loopback interface (Docker, `--host 0.0.0.0`, or systemd override). When binding `127.0.0.1`, the peer address is always loopback; the check is retained as defense in depth but adds no feature.
  - On mutating requests (`POST`, `PUT`, `DELETE`, `PATCH`), verify that `Origin` (or `Referer`) matches the allowed host/port scheme. Reject mismatched or external origins with HTTP `403 Forbidden`.
  - IPv6 allowlist entries: include both bracketed (`[::1]:8080`) and bare (`::1`) forms; the Host-header check compares against the exact string the client sent, so both must be in the set.
* **CLI Environment Variables**:
  - `--host: str = typer.Option("127.0.0.1", "--host", envvar="PCUR_HOST")`
  - `--port: int = typer.Option(8080, "--port", "-p", envvar="PCUR_PORT")`
  - `--token: str | None = typer.Option(None, "--token", envvar="PCUR_AUTH_TOKEN")`

### 2.2 Process Control: XDG PID File (`photocure stop` / `kill`)
* **PID File Creation**:
  * On server startup, write the current PID to `$XDG_RUNTIME_DIR/photocure/<port>.pid` (fallback: `~/.cache/photocure/run/<port>.pid`).
  * Remove the PID file cleanly on server shutdown (`SIGTERM`, `SIGINT`, or clean exit hook via `atexit.register`).
* **Safe CLI Commands**:
  * Implement `photocure stop [--port 8080] [--force]`:
    1. Read PID from `$XDG_RUNTIME_DIR/photocure/<port>.pid`. If not found, output: `"No active Photocure server found on port <port>."` and exit 0.
    2. Verification: Check `os.kill(pid, 0)`. On Linux, verify `/proc/<pid>/cmdline` contains `"photocure"`. On macOS, verify via `ps -p <pid> -o command=`. On Windows (not a supported deployment target per §1 Supported Platforms), skip the cmdline check and warn. If the PID was recycled by another program, abort immediately without killing.
    3. Termination: Send `SIGTERM`, poll for process termination for up to 5 seconds.
    4. If process is still alive after 5 seconds:
       - If `--force` was passed, send `SIGKILL`.
       - If `--force` was not passed, warn that process did not stop and suggest `--force`.
    5. Clean up PID file upon process exit.
  * Register `photocure kill` as an exact alias to `photocure stop --force`.
  * **Strict Prohibition**: Never use `fuser -k`, `killall`, or broad `pgrep -f` that could match user text editors or shell sessions.
* **Debian Cleanup**: Delete the old `packaging/deb/prerm` script that indiscriminately killed processes, and remove its reference from `build_deb.sh`.

### 2.3 Safe In-App Server Restart with Ledger-Write Lock & Startup Crash Recovery
* **Ledger-Writing Lock Guard**:
  - Maintain a process-wide lock `_LEDGER_WRITING = threading.Lock()` acquired whenever any code path mutates original photos on disk or writes transactional rows to the ledger tables. In practice this means: `ActionEngine.execute()`, `RollbackEngine.undo()`, and any helper they call. Routine metadata writes outside the ledger (scanner inserts into `ImageRecord`, inference writing `FaceRecord`, cache cleanup) do NOT acquire this lock; those are interruptible and idempotent on restart.
  - In `POST /api/restart`:
    * If `_LEDGER_WRITING.locked()`: **STRICTLY REFUSE restart even if `force=true`**. Return HTTP `409 Conflict`:
      `{"ok": false, "error": "A filesystem transaction is actively writing. Server restart cannot be forced during plan execution or undo."}`
    * If only a background read task (scan, infer, cluster) is running:
      - If `force=false`: Return HTTP `409 Conflict` prompting the user.
      - If `force=true`: Allow restart.
    * Spawn daemon restart thread: sleep 250 ms, then `os.execv(sys.executable, [sys.executable, *sys.orig_argv[1:]])`.
* **Startup Orphaned Transaction Recovery**:
  - On server startup (`init_db` / FastAPI startup event), query SQLite ledger for any transactions with status `PENDING` (indicates mid-transaction power loss, system crash, or `photocure kill`).
  - If orphaned transactions exist:
    - Log an alert in the console.
    - Expose `GET /api/transactions/orphaned` listing incomplete actions.
    - Render a prominent notification banner in UI: *"Incomplete transaction from unexpected shutdown detected (TX_...). Resume to finish, or Undo to roll back."*
    - Endpoints: `POST /api/transactions/{tid}/resume` and `POST /api/transactions/{tid}/rollback`.
* In `photocure/ui/static/app.js` & `style.css`:
  * Add `#restart-overlay` modal with a smooth spinner and text: *"Restarting Photocure..."*
  * Poll `GET /healthz` every 500 ms. Once it responds with HTTP 200, reload `window.location.reload()`.
  * Timeout guard: After 60 seconds without response, show an error: *"Server did not restart within 60 seconds. Please run 'photocure start' from your terminal."*

### 2.4 Standalone First-Launch Bootstrap & Package Upgrades (`/opt/photocure/bootstrap.py`)
* **Standalone Script Location**: Ship `bootstrap.py` as a standalone standard-library script installed at `/opt/photocure/bootstrap.py` (Standard Library Only: `http.server`, `urllib`, `subprocess`, `sys`, `os`, `json`, `threading`, `time`, `pathlib`, `shutil`, `webbrowser`).
* **Wrapper Script Logic (`/usr/bin/photocure`)**:
  ```bash
  USER_VENV="${XDG_DATA_HOME:-$HOME/.local/share}/photocure/venv"
  VENV_CLI="$USER_VENV/bin/photocure"
  SYSTEM_VERSION="/opt/photocure/VERSION"

  # Case 1: First run - venv does not exist
  if [ ! -x "$VENV_CLI" ]; then
      exec python3 /opt/photocure/bootstrap.py "$@"
  fi

  # Case 2: Package upgrade - compare version marker
  VENV_VERSION="$USER_VENV/.photocure_version"
  if [ -f "$SYSTEM_VERSION" ] && [ -f "$VENV_VERSION" ]; then
      if [ "$(cat "$SYSTEM_VERSION")" != "$(cat "$VENV_VERSION")" ]; then
          exec python3 /opt/photocure/bootstrap.py --upgrade "$@"
      fi
  fi

  exec "$VENV_CLI" "$@"
  ```
* **Upgrade Mode (`--upgrade`)**:
  - Does NOT build `venv.tmp` from scratch (preserving installed PyTorch, CUDA runtime, and cached model weights).
  - Runs `$USER_VENV/bin/pip install --no-cache-dir --upgrade /opt/photocure/wheels/photocure-*.whl`.
  - Updates `$USER_VENV/.photocure_version` with contents of `/opt/photocure/VERSION`.
  - Continues launch into `photocure serve`.
* **Healthcheck Behavior during Initial Bootstrap**:
  - During provisioning, `GET /healthz` returns **HTTP 503 Service Unavailable** (`{"status": "provisioning", "step": current_step}`).
  - The browser progress page checks `/healthz` and specifically **waits for HTTP 200 OK** before reloading, preventing premature reloads while the bootstrap server is still running.
* In `photocure/inference/backends.py`: **Never output a bare `pip install` command**. Inside a venv, output the exact venv pip binary path (`/path/to/venv/bin/pip install ...`). Outside a venv, suggest `photocure setup --reinstall`. When an active GPU backend is already functioning, never suggest a different torch build that would break it.

### 2.5 Pre-Execution SQLite Online Backup (`snapshot_database`)
* In `photocure/db/session.py`:
  ```python
  import sqlite3, contextlib
  from datetime import datetime, timezone
  from pathlib import Path

  def snapshot_database(db_path: Path | str = "photocure.db", backup_dir: Path | None = None, keep: int = 10) -> Path:
      src = Path(db_path).resolve()
      if not src.exists():
          raise FileNotFoundError(f"Database file not found: {src}")

      b_dir = backup_dir or (src.parent / "backups")
      b_dir.mkdir(parents=True, exist_ok=True)

      # UTC + ISO-ish stamp so lexicographic sort == chronological sort, DST-proof.
      timestamp = datetime.now(timezone.utc).strftime("%Y%m%dT%H%M%SZ")
      dst = b_dir / f"{src.stem}_{timestamp}.bak.db"

      with contextlib.closing(sqlite3.connect(str(src), timeout=30.0)) as src_conn:
          with contextlib.closing(sqlite3.connect(str(dst))) as dst_conn:
              src_conn.backup(dst_conn, pages=100)

      # Rotate by filename (timestamp embedded), not mtime (mtime is rewritable).
      backups = sorted(b_dir.glob(f"{src.stem}_*.bak.db"))
      while len(backups) > keep:
          oldest = backups.pop(0)
          try:
              oldest.unlink(missing_ok=True)
          except OSError:
              pass
      return dst
  ```
* Rotation is count-based (`keep`, default 10). Operators facing disk pressure should lower `keep` via config rather than adding a size cap in code.
* In `POST /api/plan/apply`: When `cfg.auto_db_backup` is true, invoke `snapshot_database()`. If it fails, log a warning, notify the client via toast, and proceed safely.

## 3. C2: Non-Destructive XMP Sidecar Writing & Safe Hardlink Organization

**Goal**: Give Photocure a durable, portable metadata store (XMP sidecars) and a zero-copy folder-organization primitive (hardlinks with safe undo). Both are internal correctness features; third-party-tool interoperability (Immich, PhotoPrism, Lightroom, darktable) is explicitly deferred (see §10 Roadmap).

### 3.1 Non-Destructive In-Place XMP Sidecar Writer

### 3.3 Zero-Storage Hardlinks, `EXDEV` Fallback & Inode/Device Ledger Tracking for Safe Undo
* In `photocure/engine/action_engine.py`:
  * Implement `_link_or_copy(src, dst, rep)` and a helper `_check_space(src, dst)` that stats `src` for size and `shutil.disk_usage(dst.parent)` for free bytes, raising `OSError(ENOSPC)` early if the copy would not fit (with a safety margin of 32 MiB).
    ```python
    try:
        os.link(src, dst)
        actual_op = "hardlink"
    except OSError as e:
        FALLBACK_ERRNOS = {errno.EXDEV, errno.EPERM, errno.EMLINK, errno.ENOTSUP, errno.EOPNOTSUPP}
        if e.errno in FALLBACK_ERRNOS:
            ActionEngine._check_space(src, dst)
            shutil.copy2(str(src), str(dst))
            actual_op = "copy"
            rep.copy_fallbacks += 1
            # Distinguish EPERM (likely fs.protected_hardlinks=1 or ACL) from EXDEV (cross-fs)
            # so operators can diagnose unexpected copies instead of assuming cross-mount.
            if e.errno == errno.EXDEV:
                log.warning("Cross-filesystem link (EXDEV); copied instead of hardlinking: %s -> %s", src, dst)
            elif e.errno == errno.EPERM:
                log.warning("Hardlink refused (EPERM, likely protected_hardlinks sysctl or ACL); copied: %s -> %s", src, dst)
            else:
                log.warning("Hardlink unsupported (errno=%s); copied: %s -> %s", e.errno, src, dst)
        else:
            raise  # Propagate ENOSPC (disk full) or other fatal errors
    ```
  * **Ledger Device/Inode Provenance**:
    - When writing ledger entries, record `entry.actual_operation` (`"hardlink"` vs `"copy"`), along with `entry.target_dev` and `entry.target_ino` (from `os.stat(dst)`), and `entry.sha256` + `entry.file_size`.
* **Safe Undo in `RollbackEngine` (Survives Source Directory Cleanup)**:
  - Users frequently clean up their SD card or import dump folder after curating, causing `os.path.samefile(src, dst)` to fail because `src` is gone.
  - **For `"hardlink"`**: Stat `dst`. Compare `(st.st_dev, st.st_ino) == (entry.target_dev, entry.target_ino)`. If it matches, the target is definitively the exact hardlink created by Photocure. Safely unlink `dst`. If dev/ino do not match (file replaced by user), abort deletion and log warning.
  - **For `"copy"` (including copy fallbacks)**: Stat `dst`. Verify `file_size(dst) == entry.file_size` and `file_sha256(dst) == entry.sha256`. If verified, unlink `dst`.
* UI Notification: When `rep.copy_fallbacks > 0`, display a banner: *"Cross-filesystem link detected; files were copied instead of hardlinked."*
* Docker Documentation: Detail the common-parent mount (`-v /mnt/storage:/media:rw`) with `/media/raw` and `/media/curated` so hardlinks succeed.

### 4.3 Two-Stage Detection: YuNet Full-Frame + Crop Downscale to 512px
1. **Stage 1 (Downscale Scan)**: Run YuNet on a frame downscaled to at most 1280px on its longest edge. Detects all face bounding boxes $[x_1, y_1, x_2, y_2]$ (normalized 0..1).
2. **Stage 2 (Full-Resolution Crop)**: Map normalized coordinates back to the full-resolution, EXIF-oriented frame. Crop each face with a **20% margin** from the full-resolution pixels (for RAW, use the embedded preview if $\ge 1280$px, else half-size demosaic).
3. **Minimum Size Gate**: If face crop width $< 60$ px (`face_min_px`, tune), set `eye_status = "unknown"` and skip steps 4 to 6 (save `face_sharpness = None`). **Unknown is never scored as open or closed.**
4. **Sharpness First (independent of landmarker)**: Compute `face_sharpness` as the Laplacian variance of the full-resolution crop resized to a fixed 128px width. Doing this before landmarker downscale keeps sharpness values comparable across subjects regardless of distance and independent of landmarker success.
5. **Pre-Landmarker Crop Downscale**: If the cropped face image exceeds 512px on its longest edge, downscale it to max 512px before feeding it to MediaPipe `FaceLandmarker`. (MediaPipe's internal input tensor is ~256px; processing full 1500px+ crops wastes CPU cycles and memory without accuracy gain.)
6. **Landmark Inference**: Run MediaPipe `FaceLandmarker` task on the downscaled crop. If no face or no blendshapes returned, set `eye_status = "unknown"`.

### 4.4 MediaPipe FaceLandmarker & Single Blink Signal
* Calculate a single normalized score per face:
  $$\text{eye\_closed\_score} = \frac{\text{eyeBlinkLeft} + \text{eyeBlinkRight}}{2.0} \quad \in [0.0, 1.0]$$
  Do not compute or store EAR; a single blendshape signal avoids contradictory outputs.
* **Pure Classification Function**:
  ```python
  def classify_blinks(tracks: list[list[tuple[int, float | None]]], *,
                      closed_hi: float = 0.75,
                      possible: float = 0.50,
                      rel_delta: float = 0.35,
                      rel_floor: float = 0.40,
                      pct: float = 15.0) -> dict[tuple[int, int], str]:
      """Pure classification function with zero model dependencies for clean unit testing.

      tracks: list of face tracks, where each track is [(frame_idx, eye_closed_score)]
      returns: {(track_idx, frame_idx): 'open' | 'possible' | 'closed' | 'unknown'}

      Rules per frame score s:
        - s is None                           -> "unknown"
        - s >= closed_hi                      -> "closed" (single-frame absolute rule, always applies)
        - base available AND
            s >= rel_floor AND
            (s - base) >= rel_delta           -> "closed" (burst-relative rule)
        - s >= possible                       -> "possible"
        - otherwise                           -> "open"

      Single-frame fallback: when a track has fewer than 3 non-None scores, `base` is None and
      only the absolute `closed_hi` / `possible` thresholds apply. This prevents a lone
      narrow-eyed sample from being miscalled "closed" by a noisy relative baseline.
      """
      import numpy as np
      out = {}
      for ti, track in enumerate(tracks):
          scores = [s for _, s in track if s is not None]
          base = float(np.percentile(scores, pct)) if len(scores) >= 3 else None
          for fi, s in track:
              if s is None:
                  out[(ti, fi)] = "unknown"
              elif s >= closed_hi or (base is not None and s >= rel_floor and (s - base) >= rel_delta):
                  out[(ti, fi)] = "closed"
              elif s >= possible:
                  out[(ti, fi)] = "possible"
              else:
                  out[(ti, fi)] = "open"
      return out
  ```
* Only `"closed"` sets `face.is_blink = True` and contributes to `ImageRecord.has_blinks`. `"possible"` acts as a visual caution indicator without triggering ranking penalties.

### 4.5 Burst-Relative Adaptive Baseline & Greedy IoU Spatial Tracking
* **Greedy IoU Tracking**: Track faces between consecutive frames (in capture order) using spatial IoU matching $\ge 0.45$. A face without a match starts a new track and is evaluated under single-frame rules. Never match across different bursts.
* **Outlier Immunity**: The baseline is the 15th percentile of the subject's own closed-scores across $\ge 3$ frames in that burst. A single wide-eyed frame or landmark flutter cannot distort the baseline.

  ```javascript
  export function computeWindow({ scrollTop, gridTop, viewportH, rowH, cols, total, overscanRows = 2 }) {
    if (total === 0 || cols === 0 || rowH === 0) {
      return { startIdx: 0, endIdx: 0, offsetY: 0, totalHeight: 0 };
    }
    const totalRows = Math.ceil(total / cols);
    const totalHeight = totalRows * rowH;
    const relScroll = Math.max(0, scrollTop - gridTop);
    const startRow = Math.max(0, Math.floor(relScroll / rowH) - overscanRows);
    const endRow = Math.min(totalRows, Math.ceil((relScroll + viewportH) / rowH) + overscanRows);
    return {
      startIdx: startRow * cols,
      endIdx: Math.min(total, endRow * cols),
      offsetY: startRow * rowH,
      totalHeight
    };
  }
  ```

### 7.3 Systemd User Unit (`packaging/deb/photocure.service`)
* ExecStart: `/usr/bin/photocure serve --no-open` (binds to loopback `127.0.0.1` by default).
* Lifecycle: `Restart=on-failure`, `RestartSec=5s`, `StartLimitBurst=5`, `StartLimitIntervalSec=60s`, `Environment=PYTHONUNBUFFERED=1`. The start-limit pair prevents an infinite restart loop on port conflicts or missing venv.
* Not enabled by default. Document user activation:
  ```bash
  systemctl --user daemon-reload
  systemctl --user enable --now photocure
  ```
* Document LAN access via systemd drop-in override: `Environment=PCUR_HOST=0.0.0.0` with `EnvironmentFile` (mode 0600) setting `PCUR_AUTH_TOKEN`.

### 7.4 Non-Root Containerization (PUID / PGID, Auto-Token & Healthchecks)
* **Entrypoint shim** (`docker/entrypoint.sh`): Container starts as root solely to execute the shim, which:
  1. Reads `PUID` (default 1000) and `PGID` (default 1000).
  2. If a non-root `photocure` user with those IDs does not exist, creates group+user with `groupadd -g $PGID photocure && useradd -u $PUID -g $PGID -s /usr/sbin/nologin -d /data photocure`.
  3. `chown -R photocure:photocure /data` (idempotent, bounded to the data volume; never touches `/opt` or `/usr`).
  4. `exec gosu photocure:photocure photocure serve --host 0.0.0.0 --port 8080 "$@"`.
  Rationale: `USER photocure` baked into the Dockerfile breaks when host UIDs differ; the shim preserves file-ownership parity with the host. `gosu` is used (not `sudo` or `su`) to avoid TTY and signal-forwarding issues.
* Dockerfile installs `gosu` from the distro repo (`apt-get install -y --no-install-recommends gosu`) and documents the GPG verification step.
* Expose `HEALTHCHECK` checking `http://127.0.0.1:8080/healthz`.
* Publish port on `127.0.0.1:8080:8080` by default in docs and Compose examples.
* Data volume mounted at `/data`.
* Auto-generate token if missing on first launch when binding `0.0.0.0`, save to `/data/auth_token` with mode `0600`, and log prominently to stdout. Document setting `PCUR_AUTH_TOKEN` in `docker-compose.yml`.


### Post-Commit Regression Rollback
Each commit group's final commit is tagged `cN-done` (annotated) on `develop`. Rollback procedure:
1. Identify the offending group tag (`git tag --list 'c*-done'`).
2. On `develop`: `git revert <range>` covering every commit in that group (`git log cN-prev..cN-done` gives the range). Keep each revert as a dedicated commit with subject `revert(C<n>): <reason>`.
3. Users on the released `.deb` roll back by `apt install photocure=<previous-version>` (publish the prior `.deb` alongside the current one in GitHub Releases).
4. DB rollback: the latest pre-execution snapshot from §2.5 (`backups/photocure_YYYYMMDDTHHMMSSZ.bak.db`) is the restoration source; `photocure db restore <snapshot>` is added in C1 and documented. The ledger is append-only, so partial rollbacks preserve prior-group transactions.
5. Sidecar changes made by a reverted group are NOT auto-rolled-back; §3 ledger entries let the user Undo the batch from the UI if desired.

### Manual Release QA Checklist (Release Candidate)
1. **Fresh Desktop Install & Icon Check**:
   - Install `.deb` on a clean Ubuntu 24.04 desktop using available package installers (GNOME Software, gdebi, App Center). Note icon rendering as best-effort.
   - Verify Application Menu displays the full Photocure logo upon installation.
   - Launch from GNOME Application Menu. Observe bootstrap progress page in browser, followed by automatic reload into main dashboard once `/healthz` returns 200.
2. **Culling & Blink Calibration**: Import a folder containing camera bursts and group portraits. Verify that photos where subjects blinked show the "Blink" badge, and "Inspect Faces Zoom" displays tight crops with openness scores.
3. **Hardlink & Fallback Verification**:
   - Organize on same filesystem: verify target files share inodes with originals (`ls -i`).
   - Organize across mount points: verify automatic fallback to copy with warning banner.
   - Run Undo: verify both hardlinks (checked via st_dev/st_ino) and copied files (checked via size and sha256) are cleanly rolled back, even if original import folder was deleted.
4. **Sidecar Round-Trip Preservation**: Pass an `.xmp` fixture containing diverse namespaces (`crs:`, `lr:`, `photoshop:`, unknown) through Photocure. Verify every non-Photocure-owned element remains byte-for-byte identical while star ratings update. This is Photocure-internal correctness; third-party-tool consumption is out of scope and tracked in §10 Roadmap.
5. **Benchmark Publication**: Run `photocure bench pipeline <test_folder>` and record the output in `docs/benchmarks.md`.

## 9. Maintainer Clarifications & Decision Log

1. **Third-Party Photo Manager Interop Deferred**: Immich, PhotoPrism, Lightroom, and darktable integration (shared library mounts, rescan webhooks, verified `xmp:Rating`/`dc:subject` consumption, `xmp:Rating = -1` behavior) is **explicitly out of scope** for C1 to C6. See §10 Roadmap. The XMP writer is still non-destructive so that if a user later points one of those tools at Photocure's output, no third-party metadata is at risk.
2. **Star Rating Automation**: Automatic AI star ratings are **disabled by default** (`auto_rate = False`). Photocure assigns ratings only on explicit user shortcut (`1-5`) or button press, writing flat tags (`photocure-best-shot`, `photocure-blink`) to sidecars.
3. **Blink Calibration Labels**: Calibration uses the maintainer's fixture folder `tests/fixtures/faces/` for threshold sweeps, skipping gracefully if absent in CI.
4. **Repository Licensing**: Root `LICENSE` file is **MIT**. Third-party models and libraries are attributed in `NOTICE`. Author credit is **Safiyu** (`Safiyu Vattaparambil`).
5. **Package Installer Local Icon Realities**: Local `.deb` icon preview in GUI installers is best-effort due to varied installer behavior with local standalone packages. Standard hicolor hierarchy (16px to 512px) and AppStream metadata ensure standard Freedesktop menu discovery upon installation.
